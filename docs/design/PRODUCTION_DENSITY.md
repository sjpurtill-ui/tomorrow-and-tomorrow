# Production: choices with consequences

The workshop opens with the current equipment need, then a choice of current
orders, products, or equipment stores. Each task has a bounded searchable index
and one selected reading. Orders show four choices; other catalogues show six,
or four at narrower widths. The original controls still act on the original
order IDs, with their global queue positions retained after filtering.

A product explains what it equips, the real combat figures, its complete
material bill, the current blocker, and the existing start command together.
Fixed batches and retooling use the same presentation. Capacity is stated once;
the selected product retains its own material shortage. No recipe, cost, queue,
production speed, or eligibility rule changes.

Daily work selects either household stores or crafts in use. A selected town
keeps stock, target, daily output, wear, and raw materials together. A selected
craft explains adoption, actual use, and why household supply limits its benefit.
The maker allocation and existing delegation controls remain available.

Equipment stores retain exact stock, shortage, repair, and replenishment data.
Formation needs show three entries by default and an explicit searchable archive
of six. Materials and daily flow are a disclosure under the primary work area.

Selection, query, page, and the current task survive provider refreshes. Narrow
readings replace the index with a Back control, preserving search and selection.
Resizing across page capacities preserves the selected item. This is presentation
state only and adds no game-save fields.

Independent critique accepted the revised rendered household, product, equipment,
and craft views. Private GPU validation covers both palettes at 1024, 1600, and
2869 pixels, including nested catalogues and search. Focused checks cover live
order updates, filtered last-item actions, bounded navigation, and original
production behavior. See the integration log for final checkpoint results.
