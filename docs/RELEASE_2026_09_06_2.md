# Stable foreign district rendering

Release 2026.09.06.2, source codex/district-hover-fix from db0419b.

Foreign settlement visuals previously used a serialized list of complete, aging intelligence reports as a shared rebuild key. Advancing days changes nested field uncertainty; nearby lookouts also return varying estimates. Either change destroyed and recreated all visible districts, sometimes changing their apparent footprint/building layout. Camera distance sorting could also invalidate the whole list. This provides a reproducible explanation for repeated district shivering/bursts while inspecting a place.

Each district now retains its own node until its visual inputs change. Geometry uses recorded observations, while the report UI still shows dated, widening uncertainty. Overlapping new population estimates retain the existing visual population; materially different evidence outside that range updates it. Another district's reports no longer replace this one. Replaced nodes are hidden immediately before deferred deletion to avoid drawing both generations together. Camera detail changes and removal still work. No demographic, intelligence accuracy, travel or save rules change.

## Evidence

- Private-desktop GPU fixture reproducing two nearby districts: baseline logged six replacements during six days of report aging and a further replacement on an unrelated city's report.
- Same fixture after the fix: zero aging replacements; unrelated report caused no replacement. Moving the pointer and camera, repeated overlapping lookout estimates, genuinely different population evidence, city removal, and regional/close zoom transitions passed. Reviewed the 1280x720 captured render.
- 21/21 regression tests across contact report, city intelligence, contact objective and campaign chronicle passed in the feature worktree.
- Repro: tests/district_hover_probe.tscn. Requires isolated user directory TomorrowAndTomorrow_DistrictHover_Test. Baseline mode: --baseline. Logs in source worktree artifacts/hover-baseline-fixedprobe.log, hover-final.log and hover-regression.log.

The fixture uses the reported district name as a label, not a copy of the user's unsaved new world. Their current exact scene was unavailable on disk. No district-specific name/proximity condition was added. Exact visual confirmation in that running scene remains pending a normal relaunch and user check. The live player PID50068 was preserved during validation; no save or restart was performed.
