# Efficient execution queue

The queue separates editorial decisions from runtime work. Do not advance a batch
because more identities are available; advance it when the preceding decision gate
is satisfied.

## P0 — approve the frame

**Work**

- Review the 24 transformations in `HIDDEN_CHRONOLOGY.md`.
- Review the 300 anchor-slot allocation.
- Review the early-game activity loop and presentation hierarchy.
- Record revisions in the decision log.

**Gate**

The campaign has an accepted beginning, reference shape, future destination, and
definition of severe anachronism.

**Testing**

None. This is editorial work.

## P1 — classify the opening spine

**Scope**

T01–T04 and every live discovery plausibly required by them.

**Work**

- Fill the first 38 anchor slots from the live ledger.
- Assign each selected discovery a transformation, role, review status, and
  presentation tier.
- Identify missing foundations and duplicate or overly broad identities.
- Trace outside-learning routes and operating requirements.
- Produce a short exception list, not a general catalog rewrite.

**Gate**

The opening causal spine is historically coherent, recoverable through valid
branches, and able to support the first playable slice.

**Testing**

No runtime tests until a repair is implemented. Deterministic ledger generation
and row-count checks are sufficient for planning artifacts.

## P2 — design the opening gameplay slice

**Work**

- Map existing exploration, settlement, seasonal, person, project, diplomacy,
  exchange, and crisis systems onto the early-game loop.
- Identify the smallest missing behaviors that prevent active play between rare
  discoveries.
- Define the normal opening research cadence only after the activity map exists.
- Choose one connected implementation wave of 20–50 discoveries and behaviors.

**Gate**

Every expected stretch without a breakthrough contains meaningful objectives,
feedback, and consequences.

**Testing**

None for the design map.

## P3 — repair and implement the first wave

**Work**

- Repair only accepted T01–T04 chronology defects.
- Implement missing operating consequences for the selected connected wave.
- Apply the four-tier announcement hierarchy.
- Preserve alternate acquisition routes and current save authorities.

**Gate**

The wave changes actual decisions and operations, not only bonuses or catalog
counts.

**Testing**

- Focused tests for changed systems while developing.
- One subsystem integration run when the wave is complete.
- One bounded opening playthrough emphasizing decision cadence and clarity.
- No millennial simulation and no complete regression suite during individual edits.

## P4 — review the next transformation before implementing it

Repeat the same order for T05 onward:

1. classify anchors;
2. repair the causal stack on paper;
3. select supporting discoveries;
4. design the gameplay change;
5. implement one connected wave;
6. test the completed wave once.

A later transformation may be planned while the prior implementation is stable,
but it does not enter runtime early merely because its identities already exist.

## P5 — hidden-era milestone reviews

At the end of H01, H02, H03, H04, H05, and H06:

- review the accumulated narrative against the reference chronology;
- inspect the shortest routes to the next horizon's anchors;
- verify that acceleration comes from operating feedback loops;
- review player interruption density;
- run the relevant integrated suites; and
- perform a bounded pacing observation appropriate to the completed horizon.

Long campaign runs become useful only after several transformations have complete
operating behavior. They are evidence, not design tools.

## P6 — draft promotion and art

An authored draft is considered for promotion only when an accepted transformation
needs it. Before promotion it receives:

- a ledger row;
- a concrete mechanism and scope;
- causal and operating stacks;
- acquisition behavior;
- presentation tier;
- AI use; and
- save-compatible implementation ownership.

Final paper-and-gouache art follows accepted identity and scope. Generate art by
connected transformation so architecture, clothing, tools, and landscape remain
historically coherent.

## Work limits that preserve time and tokens

- One transformation or one connected 20–50-discovery wave per review packet.
- One authoritative ledger; no duplicate status prose in several documents.
- Review exceptions and anchors deeply; use concise classifications for ordinary
  supporting methods.
- Do not rerun evidence when neither the relevant code nor its dependencies changed.
- Do not use a long simulation to answer an editorial question.
- Do not generate final art for an unaccepted identity.
- Do not activate a draft simply to increase catalog coverage.
- Record accepted decisions once and cite them in later work.

4. a proposed first implementation wave; and
